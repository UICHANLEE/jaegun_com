# 재건 공동체

교회별 소식, 게시판, 1:1 채팅, 사진·영상 업로드와 역할 기반 가입 승인을 제공하는 반응형 커뮤니티 서비스입니다. 프로덕션 웹 앱은 `apps/web`, Supabase 데이터베이스·보안 정책은 `supabase`에 있습니다.

## 주요 기능

- 이메일 로그인과 신규 가입, 교회·역할 선택 온보딩
- 엑셀 명단에서 **교회명만** 추출한 36개 초기 조직
- 공지·나눔·기도·사진/영상 게시판과 댓글
- 비공개 1:1 채팅
- 교회별 소개, 예배 안내, 조직 상태 표시
- 플랫폼 관리자: 사역자·임원 승인
- 교회 사역자/임원: 자신의 교회 일반 회원 승인
- 권한별 모바일 화면: 성도 참여 홈, 사역자 사역 홈, 임원 운영 홈·내비게이션 분리
- 임원 직책(회장·부회장·총무·서기·회계) 복수 선택과 연도별 직책 배정
- 플랫폼 관리자용 교회별 임원직 연도 갱신(현재·차년도)과 변경 감사 기록
- 임원직·회의록·회계장부의 연도 경계는 서버가 계산한 한국시간(`Asia/Seoul`) 기준을 클라이언트와 공유
- 임원 전용 연도별 회의록·회계장부, 직책별 작성 권한과 실제 수입·지출·잔액 집계
- 집사·권사·장로·전도사·목사 직분을 권한과 분리해 표시·승인
- 15MB 사진과 500MB 영상, 대용량 재개 가능 업로드

승인 권한은 화면 표시, 교회 직분, 임원 직책이 아니라 `platform_admin`과 `minister | executive | member` 역할로 결정됩니다. 회의록·회계장부의 세부 작성 권한은 승인된 연도별 임원 직책을 함께 검사하며, 두 단계 모두 Supabase RLS·보안 RPC로 강제됩니다. 브라우저에는 서비스 역할 키를 넣지 않습니다.

## 로컬 실행

```bash
npm ci --prefix apps/web
npm run dev:web
```

환경 변수가 없으면 실제 서비스와 동일한 화면·상호작용을 확인하는 명시적 데모 모드로 실행됩니다. 실제 인증과 저장을 연결하려면 다음 파일을 만듭니다.

```bash
cp apps/web/.env.example apps/web/.env.development.local
```

```dotenv
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_OR_PUBLISHABLE_KEY
```

개발용 연결은 `.env.development.local`, 배포 빌드는 `.env.production.local` 또는 배포 환경 변수로 분리합니다. 이렇게 하면 단위 테스트(`test` 모드)가 운영 DB를 사용하지 않습니다. 실제 프로젝트를 연결한 로컬 앱의 작성·삭제 작업은 운영 데이터에 반영되므로 데모 계정처럼 사용하지 마세요. 공개 키만 사용하고 로컬 환경 파일은 커밋하지 않습니다.

2026-10-11 실제 연결 및 채널 마이그레이션 적용 근거: [운영 DB 연결 점검](docs/qa/2026-10-11/live-connection.md).

### 회원 홈 위젯과 기기 테마

선택한 B 피드형을 실제 회원 홈 `/app/home`에 적용했습니다. 공지·게시글·소모임·예배/일정은 `apps/web/src/components/home/`의 독립 컴포넌트입니다. **홈 편집**에서 표시/숨김, 위·아래 순서 이동, 숨긴 항목 추가, 기본 구성 복원이 가능하며 저장 전에는 미리보기만 바뀝니다. 최소 한 개의 위젯을 유지합니다.

구성은 `jaegun-home-widgets-v1:` 키 아래 현재 기기의 `localStorage`에 저장합니다. 실서버/데모 모드·계정·교회별로 분리하며 서버 동기화나 공동체 데이터 저장은 하지 않습니다. 저장이 차단되면 현재 화면에만 적용했다는 안내를 표시하고, 손상되거나 지원하지 않는 설정은 기본 구성으로 복원합니다.

`apps/web/src/theme.css`의 의미별 색상 토큰과 `prefers-color-scheme`으로 기기 설정을 자동 적용합니다. 앱이 열린 상태에서 테마를 바꿔도 새로고침할 필요가 없습니다. 별도 테마 설정은 저장하지 않으며 실제 로고 색상과 래스터 자산을 유지합니다. iOS는 상태바의 기존 non-overlay 배치를 유지하고, UIKit의 적응형 창 배경과 기본 상태바 스타일로 네이티브 영역을 기기 테마에 맞춥니다. 강제 밝은 키보드 설정은 제거했습니다. 웹 스타일은 보안 초기화 전에 로드하여 초기화 실패 화면에도 테마를 적용합니다. 시작 스플래시의 기존 크림색은 유지합니다.

적용 화면: [라이트](design/member-home-light.png) · [다크](design/member-home-dark.png) · [위젯 편집](design/member-home-editor-dark.png).

검증 범위: 웹에서 위젯 편집·저장·재접속 복원·계정 분리와 열린 화면의 라이트/다크 전환을 확인했습니다. 초기 iOS 시뮬레이터 검증은 Keychain 초기화 실패에서 중단됐으나, 2026-10-14 서명 팀 설정 수정 후 Keychain 준비와 정상 로그인 화면 실행을 확인했습니다. 정상 로그인 이후 네이티브 화면과 키보드는 별도 실기기 검증이 필요합니다.

### 모임 개최자·참석 명단·조/차량 배정

기존 일정 `/app/events`에서 개최자를 명시하며, 입력한 이름과 실제 등록자의 감사 기록은 분리합니다. 기존 개최자 없는 일정은 `미등록`으로 표시합니다. 일정 생성·수정 권한은 기존 조직 범위의 회장·목사·위임 관리자 정책을 유지합니다.

상세 화면의 **참석자·배정 관리**에서 현재 동의·소속이 유효한 참석 응답을 확인하고 조·차량을 추가하거나 개별/자동 배정할 수 있습니다. 해당 교회의 활성 임원과 기존 정확한 범위의 일정 관리자만 접근할 수 있으며, 다른 교회 임원·일반 회원·단순 교역자·상위 조직 직책만으로는 권한이 생기지 않습니다. 명단은 이름·응답·배정 정보만 제공하고 연락처·이메일·프로필 비공개 필드는 포함하지 않습니다.

배정은 반복 일정 전체가 아닌 **회차별** 계획입니다. 참석 확정자만 배정하며 운전자가 좌석 한 개를 차지합니다. 자동 배정은 저장 전 편집 가능한 미리보기이고, 좌석이 부족하면 초과 인원은 미배정으로 남습니다. 저장은 서버에서 원자적으로 처리하며, 다른 관리자의 수정·참석 변경으로 버전이 바뀌면 기존 초안을 덮어쓰지 않고 최신 명단 확인을 요구합니다. 불참 변경·동의 철회·소속 해제 시 기존 배정과 부적격 운전자는 정리됩니다.

실제 격리된 Supabase 로그인·TOTP 인증을 거쳐 개최자 등록/수정 보존, 4명 조 편성, 운전자 포함 2석 배정·초과 2명 미배정, 저장 후 재접속 복원을 검증했습니다. 동시 저장은 하나만 성공하며, 일반 회원의 명단 조회는 차단됩니다. [360px 다크 화면](design/event-logistics-dark.png).

운영 웹은 [재건 공동체](https://jaegun-com.vercel.app)에 배포했습니다. 운영에서는 로그인/가입 화면, 필수 동의 5개, 기기 테마 전환, 보호 경로의 로그인 이동 및 비로그인 명단/배정 RPC 차단을 확인했습니다. 실제 운영 계정으로 로그인한 뒤의 모임 관리는 검증하지 않았으며, 위 기능 검증은 격리된 실제 Auth·DB 환경에서 수행했습니다.

### iOS·Android 모바일 앱

`apps/web`의 동일한 서비스 화면을 Capacitor 앱에 로컬 번들로 포함합니다. 원격 웹사이트를 앱 시작 주소로 사용하지 않으며, 운영 번들에는 데모 계정·모의 관리 데이터를 포함하지 않습니다. 모바일 화면은 안전 영역·키보드·하단 내비게이션에 대응하고 기기의 라이트/다크 설정을 따릅니다.

```bash
npm --prefix apps/web run native:build:ios
npm --prefix apps/web run native:build:android
npm --prefix apps/web run native:verify:built:android
npm --prefix apps/web run native:test:android
```

iOS 시뮬레이터 빌드는 앱 서명과 Mach-O에 포함된 Keychain용 application identifier까지 자동 검사합니다. Debug·Release의 서명 팀은 현재 로컬 개발 계정으로 고정했으며, 최종 법인 계정·App ID·스토어 제출 승인을 의미하지 않습니다. Android 기기 테스트는 `:app:connectedDebugAndroidTest`로 앱의 보안 저장소 테스트만 실행합니다. 상위 Gradle 작업으로 실행하면 생성된 Cordova 모듈의 별도 테스트 의존성에서 Kotlin 중복 클래스 오류가 발생하므로 그 모듈의 테스트와 구분합니다.

2026-10-14 검증: 320·360·430px에서 홈·게시판·채팅·교회·AI·내 정보·일정의 가로 넘침 없음, 360px 홈 순서 변경 저장/재접속 복원과 데모 메시지 전송, 열린 홈의 라이트/다크 전환을 확인했습니다. iOS 시뮬레이터에서 실제 Keychain 준비용 항목 생성·삭제와 정상 로그인 화면을 확인했습니다. Android API 36 에뮬레이터에서 APK 설치·정상 로그인 화면과 보안 저장소 기기 테스트 3개 통과를 확인했습니다. ATD 이미지의 검은 화면은 앱이 아닌 `debug.hwui.drawing_enabled=0` 설정 때문이며, 검증 에뮬레이터에서만 렌더링을 켰습니다.

연결된 iPhone 16용 Apple Development 서명 빌드·기기 설치·앱 실행을 완료했으며 기기에서 앱 프로세스가 실행 중임을 확인했습니다. 최초 실행은 기기 잠금으로 차단됐고 잠금 해제 후 재시도에 성공했습니다. 실사용 계정 로그인·네이티브 모임 배정·가입 이메일 링크의 end-to-end 검증은 수행하지 않았습니다.

스토어 배포는 별도입니다. 현재 `native:check:store`의 서명 팀·로컬 인증서 검사는 통과하지만 운영 Universal Link 응답이 필요한 JSON이 아니어서 실패합니다. 최종 법인 계정·서명 Archive·TestFlight·심사 계정·운영 삭제/신고 절차와 Android 조직 릴리스 서명은 [출시 게이트](docs/releases/ios-app-store-1.0.md)를 충족해야 합니다.

개발 서버의 `/design-review.html`에서 세 가지 정보 배치안을 비교합니다: A 요약형, B 피드형, C 도구형. 회원 홈·교회 선택·필수 동의·임원 운영을 전환할 수 있습니다. 감성 카피와 장식용 히어로를 사용하지 않고 재건 로고에서 추출한 주황 `#FC8401`, 초록 `#67B42A`, 파랑 `#0498E1`을 포인트로 사용합니다.

## Supabase 적용

1. Supabase 프로젝트를 생성합니다.
2. `supabase/migrations`의 마이그레이션을 순서대로 적용합니다.
3. `supabase/seed.sql`을 적용해 36개 교회를 생성합니다.
4. 첫 운영자 계정을 만든 뒤 `supabase/README.md`의 절차로 `platform_admin` 권한을 부여합니다.
5. 위 공개 URL/키를 로컬과 Vercel 환경 변수에 등록합니다.

세부 스키마, RLS 정책, 승인 흐름과 운영자 부트스트랩은 `supabase/README.md`를 참고하세요.

## Vercel 배포

저장소 `git@github.com:UICHANLEE/jaegun_com.git`의 루트 `vercel.json`을 사용합니다. `main` 푸시는 프로덕션 배포, 그 외 브랜치와 PR은 미리보기 배포가 됩니다.

Vercel 프로젝트에는 다음 공개 환경 변수만 등록합니다.

- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`

`SUPABASE_SERVICE_ROLE_KEY`나 데이터베이스 비밀번호를 Vite 환경 변수로 등록하면 안 됩니다.
