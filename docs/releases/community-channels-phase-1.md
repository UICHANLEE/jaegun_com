# 자유 채널 1차 구현

## 범위

- 승인 및 현재 필수 동의를 완료한 회원 누구나 자기 교회에 공개/비공개 채널 생성.
- 공개는 **인터넷 전체가 아닌 해당 교회 내부** 공개. 비공개는 초대 수락 전 대화 접근 불가.
- 채널 목록/검색, 초대 수락·거절, 참여·나가기, 공동 관리자 지정·해제, 소유권 이전, 보관.
- 텍스트 메시지, 최근 50개 및 이전 대화, 읽지 않은 수, 전송 실패 재시도와 동일 요청 중복 방지.
- 메시지 신고는 기존 운영자 신고함에 포함. 제재는 기존 교회/플랫폼 권한과 MFA를 유지. 채널 소유자라는 이유만으로 신고함을 볼 수 없음.
- 차단한 사용자 메시지/참여자 정보는 조회 시 제외. 기존 개인 대화는 유지.

## 의도적으로 제한한 사항

- 이번 단계는 교회 내부 채널만. 노회·총회·교회 간 채널, 스레드, 멘션, 일정/할 일, 파일 첨부, 채널 푸시 알림은 아직 미구현.
- 10초 간격 서버 조회 방식이며 WebSocket 실시간 채팅 완료로 표현하지 않음. 조회/전송은 15초 시간 제한. 실패하면 이전 조회 결과를 숨기고 재시도 경로를 제공.
- 공개/비공개 전환은 미제공. 참여한 회원은 과거 대화를 볼 수 있음을 생성 화면에 안내.
- 공개 채널에서 내보낸 회원은 재참여 가능. 영구 채널 차단은 아직 미제공이며 괴롭힘은 사용자 차단·신고 및 교회 회원 제재로 처리.
- 과도한 생성 방지를 위해 회원당 시간당 5개, 교회당 200개 채널 제한. 메시지는 분당 30개, 4,000자. 보관 후 복구 UI는 후속 범위.
- 운영 배포 전 300명 부하 시험과 다중 클라이언트 지연/권한 회수 SLA 검증이 추가로 필요. 자동 테스트 통과를 부하 시험으로 대체하지 않음.

## 보안 경계

- 새 3개 테이블은 RLS 활성화 및 클라이언트 직접 권한 전부 회수. 인증 주체를 직접 검증하는 private 함수와 제한된 공개 RPC만 제공.
- 사용자 입력 role/JWT user_metadata가 아니라 실제 조직 회원, 채널 참여, 현재 동의 기록으로 판단.
- 채널 관리 권한은 교회 임원/사역자/거버넌스/부서 권한을 전혀 부여하지 않음.
- 회원 자격 중지·이동·삭제 시 채널 참여와 초대를 제거. 복귀만으로 비공개 권한이 부활하지 않음.
- 프로필 비활성화/삭제 시 소유 채널을 보관하고 참여 기록 제거. 프로필 최종 삭제 시 작성한 채널 메시지는 FK cascade로 삭제. 신고 증거는 기존 신고 보존 정책을 따름.
- 소유권 변경과 관리 작업은 감사 기록. 심각한 유해 표현은 기존 서버 필터 적용.
- 프런트는 서버 응답의 actorId를 검증하고 계정 전환 시 채널 상태/진행 중 화면 처리를 폐기. 채널 데이터를 localStorage에 저장하지 않음.

## 확인한 증거

- 최종 전체 실행: 웹 테스트 240개, DB pgTAP 663개, Edge 보안 테스트 34개 통과. Xcode iOS 무서명 Release 빌드·번들 검증 및 보호 런타임 28개 파일 검사 통과. 이 결과는 App Store 제출 또는 운영 배포 완료를 의미하지 않음.

- 채널 DB 회귀 47개: 공개/비공개, 초대 수락, 교회 경계, 동의 갱신, 차단, 중복 요청, 소유권 이전, 보관, MFA 신고 제재, 계정 삭제 정리.
- 채널 화면 테스트 7개: 일반 회원 생성, 비공개 기본값, 실패 초안 보존, 요청 ID 재사용, 중복 클릭 방지, 전송 중 새 초안 보존, 계정 변경, 일반 참여자의 관리 UI 제한, 공급자 오류 비노출을 각 시나리오에 포함.
- API 경계 테스트 5개: actor 바인딩, 조직/채널/페이지 범위, 요청 주체 고정, 조회 타임아웃, 오류 비노출.
- 로컬 합성 계정으로 브라우저 로그인 → 개인 대화 → 채널 목록 → 비공개 채널 생성 → 메시지 전송 → 새로고침 후 유지 확인.
- 모바일 390px에서 가로 넘침 없음 확인. 채널 목록의 기존 5개 하단 메뉴 유지.
- 보안 진단에서 로컬 오류 없음. 운영 회원 데이터는 테스트에 사용하지 않음.

## 운영 반영 순서

1. 새 마이그레이션의 원격 미적용 상태와 기존 버전 일치 확인.
2. 마이그레이션을 운영에 적용하고 익명/비회원 접근 거부 및 공개 RPC 확인. 테스트 계정·채널은 운영으로 복사하지 않음.
3. 웹 배포 후 승인된 합성 검증 계정으로 채널 생성/초대/신고를 재검증.
4. iOS 번들을 새로 빌드하고 TestFlight에서 키보드·백그라운드·네트워크 전환을 확인. 기존 App Store 출시 차단 항목은 그대로 유지.

로컬 브라우저 검증은 `vite.local-db.config.ts`의 명시적 개발 서버에서만 같은 출처 프록시를 사용한다. 해당 설정은 빌드 명령을 거부하며 운영 CSP/환경 변수를 변경하지 않는다.
