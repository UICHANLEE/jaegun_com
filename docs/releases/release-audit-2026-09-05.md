# 2026-09-05 출시 점검 및 후속 실행 순서

판정: **App Review 제출 보류**. 코드 수정과 무서명 빌드는 심사 제출·실기기 검증을 대체하지 않는다. 이번 점검은 소스, 자동 테스트, Xcode 빌드, 공개 HTTP 응답에 근거한다. 브라우저 제어 도구가 연결되지 않아 실제 화면·VoiceOver·기기 상호작용은 검증하지 못했다.

## 위험도 및 조치

| 위험도 | 발견 사항 | 조치 / 해제 근거 |
| --- | --- | --- |
| 출시 차단 | Xcode Development Team 미설정, 최종 Bundle ID 미확정 | 조직 Apple 계정의 Team ID와 최종 App ID 확인 후 서명·프로비저닝·Archive 검증 필요. 로컬 서명 인증서는 감지되지만 이 앱/조직과의 일치 여부는 미검증 |
| 높음 | AASA 주소가 JSON 대신 SPA HTML을 반환 | 최종 Team ID와 Bundle ID가 있어야 정확한 인증·복구 Universal Link 파일을 배포할 수 있음. 임의 ID나 광범위 경로로 우회하지 않음 |
| 높음 | 계정 삭제 운영 완료 증거 없음 | GitHub의 두 활성화 변수는 이번 조회에서 반환되지 않음. 이는 Supabase Cron 부재의 증거는 아니며, 별도 provider 상태·삭제 완료·알림 수신 증거가 필요. 운영 데이터 삭제 워커를 임의 실행하지 않음 |
| 높음 | UGC 신고 대응 인력·SLA, 심사 계정, 실기기 시험 미완료 | 기존 삭제/신고 운영 문서에 담당자와 합성 계정 검증 증거를 채운 후 제출 |
| 중간 · 수정 | 익명 초기 조회 재시도 중 전체 로딩 화면이 가입 폼을 교체하여 입력이 사라질 수 있음 | 이미 표시된 폼 유지. 실패→가입 입력→수동 재조회→이름·이메일 보존 회귀 테스트 추가 |
| 중간 · 수정 | 예약된 자동 재시도가 이전 세션 기준으로 시작될 위험 | 타이머 실행 직전 세션 세대·사용자·차단 상태 재확인. 재시도 2회 상한 및 예약 중 unmount 취소 테스트 추가 |
| 중간 · 수정 | 연결 시간 초과/세션 확인 실패가 일반 오류로 표현됨 | 안전한 한국어 안내로 구분. 공급자 원문·토큰은 표시하지 않음 |
| 중간 · 잔여 | 계정 전환 게시 재시도 테스트가 첫 전체 실행에서 1회 실패 | 단독 23개 및 재실행 전체 228개 통과. 일시 실패 원인은 확정하지 않았으며 실제 계정 전환·전송 중 네트워크 변경 시험을 출시 게이트로 유지 |
| 낮음 · 수정 | 직분·관리 역할·임원직·부서 임원직의 의미가 혼동될 수 있음 | 내 정보에 접기/펼치기 안내, 44px 최소 터치 영역과 키보드 포커스 표시 추가. React 검토 기준에 따라 불필요한 상태 없이 기본 details 요소 사용 |

## 반드시 유지할 권한 구분

| 구분 | 의미 | 자동으로 부여하지 않는 권한 |
| --- | --- | --- |
| 집사·장로 등 교회 직분 | 프로필 소개 정보 | 회원 승인, 임원 운영 |
| 승인된 사역자 / 임원 역할 | 해당 교회의 회원 승인 및 역할별 운영 접근 | 다른 교회, 상위 조직, 담임목사 배정 |
| 총회·노회·교회 연간 임원직 | 명시된 조직·연도와 기능에 한정 | 상하위 조직으로 권한 전파 |
| 명시적 연간 pastor 배정 | 해당 범위의 목사 권한 및 교회 부서 임원 관리 | 일반 사역자 전원에게 동일 권한 부여 |
| 장년부·청년부·청소년부·초등부 임원직 | 해당 교회·부서·연도의 직책 정보 | 회원 승인, 회의록·회계, 거버넌스 관리 |
| 위임 | 명시한 범위·기능·만료일에 한정 | 플랫폼 관리자, 무기한 포괄 권한 |

화면 토글은 권한 부여 기능이 아니다. 실제 경계는 RLS/RPC이며 이번 안내 변경은 권한 정책을 완화하지 않는다.

## 이번 실행 근거

- `npm run test:web`: 최종 재실행 36개 파일, 228개 테스트 통과. 최초 실행의 계정 전환 테스트 실패 이력은 위에 보존.
- `npm run test:security-static`: 비밀정보 검사, 법적 문서 7개 해시, 마이그레이션 19개 정적 검사, Edge 보안 테스트 34개 통과.
- `npm run check:runtime`: 보호된 모바일 런타임 28개 파일 무결성 통과.
- `npm run preflight:ios`: Xcode 26.6 Release 기기용 **무서명** 빌드 및 iOS 번들/개인정보/권한 설정 검증. 서명 Archive·IPA 업로드와 다름.
- `npm --prefix apps/web run native:check:store`: 새 읽기 전용 게이트. Team 미설정과 AASA 실패로 의도대로 종료 코드 1. 지원·탈퇴·개인정보·이용약관 URL은 HTTP 200이나 렌더링 내용 확인과 다름.
- DB 정책은 이번 수정 대상이 아니며 로컬 DB 테스트를 이번 점검에서 새로 실행하지 않음. 직전 커밋 `0aa93aa`의 GitHub Web quality는 성공. 현재 커밋은 별도 CI 결과 확인 필요.

## App Store 제출까지 순서

1. 서비스 제공 법인 Apple Developer 조직 계정, 약관/계약, 최종 Bundle ID와 Team ID를 확인한다. 비밀번호나 인증서 개인키는 Git/채팅으로 전달하지 않는다.
2. Xcode Signing에 해당 Team을 설정하고 App ID와 Associated Domains를 맞춘다. AASA에 정확한 signup/recovery 경로를 배포한 뒤 `native:check:store`를 통과시킨다.
3. 삭제 워커 상태를 읽기 전용 점검하고, 격리된 합성 계정으로 실제 삭제·재시도·백로그/실패 알림을 검증한다. 신고 담당자·응답 기한을 확정한다.
4. 일반 회원·사역자·임원용 합성 심사 계정을 준비한다. 실회원 자료를 심사용 시드에 복사하거나 인증/MFA를 우회하지 않는다.
5. Xcode Organizer에서 서명 Archive → Validate App → App Store Connect 업로드. 수출 규정·콘텐츠 권리·법적 동의 답변은 소유자의 사실 확인 후 입력한다.
6. 내부 TestFlight에서 iPhone 설치/재설치, 인증 메일, 복구, 계정 전환, 오프라인, 게시/채팅 실패·중복, 신고/차단/탈퇴, VoiceOver/Dynamic Type를 검증한다. 아래 기존 출시 게이트의 체크리스트 사용.
7. 실기기에서 개인정보 없는 스크린샷을 확보하고 App Store Connect 설명·지원 URL·App Privacy·연령 등급·심사 계정을 입력한다. 공개/Unlisted 배포 방식은 소유자와 확정한다.
8. 모든 게이트 증거가 갖춰진 뒤 App Review 제출. 승인 이후 수동 공개 및 오류·신고·삭제 모니터링 확인. 심사 승인이나 자동 공개는 현 시점에 완료되지 않았다.
