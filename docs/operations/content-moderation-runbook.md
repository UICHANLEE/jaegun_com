# 커뮤니티 신고·차단·콘텐츠 운영 런북

## 사용자 안전 기능

게시글, 댓글, 사진·영상, 채팅 메시지, 사용자 프로필에서 신고할 수 있어야 한다. 신고 항목은 사칭·괴롭힘·혐오·성적 콘텐츠·아동 위험·자해/위협·개인정보 노출·스팸·저작권으로 구분하고 추가 설명은 선택으로 둔다. 신고 접수 후 접수번호와 예상 처리시간을 알려준다.

사용자 차단은 양방향 신규 1:1 대화, 메시지, 프로필 기반 알림을 서버에서 차단한다. 음소거는 알림만 끄며 상대에게 공개하지 않는다. 차단 여부를 클라이언트 필터에만 맡기지 않는다.

## 처리 우선순위와 SLA

| 등급 | 예 | 최초 확인 | 목표 조치 |
| --- | --- | ---: | ---: |
| 긴급 | 아동 성착취 의심, 구체적 자해·폭력 위협, 진행 중 개인정보 유출 | 15분 | 1시간 이내 격리·책임자 호출 |
| P1 | 성적 콘텐츠, 심각한 괴롭힘·혐오, 계정 탈취, 반복 위협 | 1시간 | 4시간 |
| P2 | 사칭, 일반 괴롭힘, 무단 촬영·저작권, 반복 스팸 | 4시간 | 24시간 |
| P3 | 분류 오류, 예절·품질 문제 | 1영업일 | 3영업일 |

아동 성착취 의심 자료는 운영자가 내려받거나 재전송하지 않는다. 접근을 즉시 제한하고 객체·행 ID, 신고 시각, 접근 로그를 변경 불가능한 감사기록에 남긴 뒤 지정된 안전 책임자와 법률 자문이 신고·보존 의무를 판단한다. 긴급 신체 위험은 현지 긴급기관 연결 절차를 따른다.

## 운영자 처리

1. reporter·target·actor의 최소 정보, 차단 관계, 이전 신고를 확인한다.
2. 대상 콘텐츠의 당시 스냅샷과 해시를 권한 제한 증거 저장소에 보존한다.
3. 기각, 노출 제한, 삭제, 경고, 일시 정지, 영구 정지 중 비례적인 조치를 선택한다.
4. 조치 사유, 정책 조항, 처리자, 시각, 만료와 감사 로그를 기록한다.
5. 신고자에게 결과 범주를 알리되 상대방의 개인정보나 세부 제재를 노출하지 않는다.
6. 대상자에게 이의제기 경로를 제공하고 다른 운영자가 3영업일 안에 재검토한다.

회장·목사·임원이 자기 자신, 가족, 직접 이해관계가 있는 신고를 처리하지 못하게 회피·재배정한다. 콘텐츠 운영 권한은 교회 임원 권한과 자동으로 같게 두지 말고 교육받은 별도 역할로 부여한다.

## 보존과 투명성

신고 원문·증거는 사건 종료 후 180일을 기본 제안으로 두되 개인정보 법률 검토와 legal hold가 우선한다. 불필요한 사본과 잠금화면·이메일 알림의 신고 상세는 금지한다. 월별로 신고 수, 중앙 처리시간, SLA 위반, 제재·복원·이의 인용률을 개인 식별 없이 검토한다.

커뮤니티 운영정책, 금지 콘텐츠, 지원 연락처, 예상 처리시간을 로그인 전에도 공개한다. Apple/Google 제출 전 실제 신고→운영자 조치→차단→이의제기 전체 흐름을 staging에서 증거와 함께 시험한다.
