# Supabase Auth 운영 설정

클라이언트 검사는 보조 장치일 뿐이다. 운영 Supabase Dashboard의 Auth 설정이 아래 기준을 서버에서 강제해야 한다. 설정 화면과 시험 결과를 릴리스 증거에 첨부한다.

## 비밀번호와 세션

- 새 비밀번호 최소 길이를 12자로 맞춘다. 웹 앱도 동일한 길이를 검사한다.
- Pro 이상에서는 유출 비밀번호 차단을 켠다.
- refresh token rotation을 유지하고 재사용 간격을 최소 범위로 둔다.
- 비밀번호 변경에는 현재 비밀번호 또는 최근 재인증을 요구한다.
- 고권한 계정에는 TOTP 등록과 AAL2를 강제하고, 복구 절차는 운영자 본인 확인과 감사 기록을 남긴다.

## 가입·복구 남용 방지

- 이메일 확인을 필수로 하고 운영 전용 SMTP를 연결한다. 기본 시험용 메일 발송기는 운영에 사용하지 않는다.
- 가입, 로그인, 비밀번호 재설정에 CAPTCHA를 연결하고 Auth rate limit을 실제 트래픽 기준으로 조정한다.
- 계정 존재 여부를 드러내지 않는 동일한 성공·실패 문구와 응답 시간을 유지한다.
- 허용 Redirect URL은 운영·검증된 Preview·로컬 개발의 정확한 URL만 등록하며 wildcard를 쓰지 않는다.

## 릴리스 시험

- 잘못된 이메일·비밀번호, 미확인 이메일, 유출 비밀번호, rate limit, 만료·재사용된 복구 링크를 확인한다.
- MFA 등록·로그인·기기 분실·전체 로그아웃·권한 변경 직후 세션을 확인한다.
- Auth 로그와 오류 수집에 이메일 전체, JWT, 재설정 코드, 비밀번호가 기록되지 않는지 확인한다.

운영 설정은 저장소 마이그레이션만으로 자동 적용되지 않는다. 설정이 확인되지 않으면 인증 보완을 완료한 것으로 표시하지 않는다.
