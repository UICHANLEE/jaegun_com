# ADR-001: 라이브 영상은 관리형 스트리밍을 사용한다

- 상태: 제안, 네이티브 앱 라이브 기능 착수 전 승인 필요
- 결정: Supabase Storage 또는 Realtime으로 영상을 직접 송출하지 않고, 관리형 라이브 스트리밍 공급자를 사용한다. Supabase는 방송 일정·권한·채팅·감사 메타데이터를 담당한다.

## 배경과 주요 문제

라이브는 일반 영상 업로드와 다르다. 한 개 원본을 여러 화질로 실시간 인코딩하고, 네트워크에 맞는 HLS/LL-HLS 조각으로 패키징해 CDN에서 전 세계 시청자에게 전달해야 한다.

3Mbps로 300명이 2시간 시청하면 대략 810GB, 6Mbps면 1.62TB가 전달된다. 화질별 트랜스코딩, 녹화 저장, 재시청, CDN 요청과 동시 시청 peak까지 비용에 포함된다. 모바일 송출자의 발열·배터리, 예배당 Wi-Fi 업로드 불안정, 시청자의 데이터 요금도 고려해야 한다.

지연시간에는 명확한 trade-off가 있다. 일반 HLS는 대략 10~30초로 안정적이고 저렴하며, LL-HLS는 약 2~5초, WebRTC는 1초 미만이 가능하지만 비용·운영 복잡성과 대규모 fan-out 부담이 커진다. 예배는 보통 LL-HLS 이하의 지연이 필요하지 않으며, 실시간 질의응답이 핵심일 때만 더 낮은 지연을 검토한다.

## 결정된 구조

```text
카메라/OBS/모바일 송출
        ↓ RTMP/SRT 또는 공급자 SDK
관리형 ingest + 다중 화질 transcoding + 녹화
        ↓ HLS/LL-HLS
CDN + 서명된 짧은 재생 권한
        ↓
Jaegun 앱 플레이어

Supabase: 방송 일정, 교회/노회 권한, 재생 entitlement,
          서버시각, 채팅, 신고, 감사 로그, 녹화 메타데이터
```

관리형 후보는 Mux, Cloudflare Stream, AWS IVS 같은 전용 서비스를 대상으로 한국 리전/지연, DPA·국외이전, 가격, signed playback, 녹화, 자막, 지원 SLA를 비교한다. 공개 YouTube 연동은 운영이 간단하지만 광고·추천·계정정책·개인정보와 접근제어 제약을 별도로 검토한다.

Supabase Realtime은 상태·채팅용이며 오디오/영상 바이트 전송에 사용하지 않는다. Storage는 검사가 끝난 녹화본·썸네일의 비공개 보관에 사용할 수 있지만 실시간 ingest, ABR transcoding, origin failover, 대규모 CDN을 대신하지 않는다.

## 출시 전 위험과 통제

| 위험 | 필수 통제 |
| --- | --- |
| 업로드 장애 | 유선 우선, 별도 방송망, 송출 bitrate 사전 측정, 로컬 녹화, backup encoder/휴대전화, 장애 안내 slate |
| 비용 폭증·링크 공유 | 교회별 동시 시청·분량 quota, 짧은 signed playback token, hotlink 차단, 예산 경보와 kill switch |
| 음악·설교 저작권 | 찬양·반주·영상의 송출 및 다시보기 권리 확인, takedown 담당자와 신속 비공개 처리 |
| 예배자·미성년자 개인정보 | 촬영 구역 안내와 동의, 어린이·상담·기도 대상 촬영 금지 기본값, 카메라 framing 교육, 필요 시 얼굴 비노출 |
| 부적절 영상·채팅 | 10~30초 안전 지연 선택, 운영자 panic stop, 채팅 slow mode·신고·차단, 최소 2명 moderation 당번 |
| 녹화 유출 | 라이브와 다시보기 권한 분리, 암호화, 보존 만료, 다운로드 제한, 삭제·legal hold 감사 |
| 채팅과 영상 불일치 | 공급자 program timestamp/서버시각 기준, 플레이어 위치와 채팅 epoch 매핑, DVR seek 시 정책 결정 |
| 공급자 장애 | 상태 모니터링, 대체 송출 안내 페이지, 중요 행사의 dual ingest/secondary provider 비용 검토 |
| 접근성 | 한국어 실시간/사후 자막, 자막 수정·대본, 플레이어 키보드 조작, 화면낭독 이름, 명확한 음성 제공 |

라이브를 “비공개”라고 표시하려면 추측 가능한 URL만 숨기는 것으로 부족하다. 승인된 범위·회원 상태를 서버에서 확인해 짧은 재생 token을 발급하고 탈퇴·정지·차단 시 갱신을 중단한다. 스트림 key는 송출자 화면에 상시 노출하지 않고 행사별 회전한다.

## 녹화와 보존

방송 생성 시 `녹화 안 함`, `기간 제한 다시보기`, `영구 보관`을 명시적으로 선택한다. 기본은 기간 제한이며 만료일, 공개 범위, 자막 상태와 저작권 확인자를 메타데이터로 기록한다. 라이브 신고로 격리된 영상은 일반 운영자가 재공개할 수 없고 moderation/legal hold 절차를 따른다.

## Go/No-go 기준

- 300명 목표 화질로 30분 staging 부하·비용 측정 완료
- 예배당 실제 네트워크에서 주·보조 송출과 failover rehearsal 완료
- signed playback, 녹화 권한, 탈퇴/정지 반영과 링크 공유 공격 시험 통과
- 신고·차단·panic stop·저작권 takedown 당번과 연락망 확정
- 한국어 자막과 키보드/스크린리더 플레이어 시험 통과
- 월 비용 상한, 50/80/100% 경보, 공급자 장애 대응 승인

이 기준을 충족하지 않으면 라이브 버튼을 출시하지 않고 검증된 외부 방송 링크를 권한 있는 공지로 제공한다.
