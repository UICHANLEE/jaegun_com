# 가입 직책 신청 RPC

가입 직책은 신청 사항이며 승인된 권한이 아닙니다. 총회·노회·교회·부서 신청은 가입 승인과 별도로 검토합니다. 기존 교회 임원 회원가입의 명시적 교회 직책·연도와 플랫폼 관리자 승인 규칙은 그대로 유지합니다.

- `list_signup_office_options(p_organization_id)` → `service_year`, `next_service_year`, exact ancestor `scopes`, fixed `departments`, allowed `office_codes` and `department_office_codes`. Signed-in, current-consent actor required. Derive scope IDs from this response, not church labels.
- `submit_membership_with_office_requests(p_organization_id, p_requested_role, p_client_request_id, p_applicant_note?, p_requested_church_title_code?, p_requested_executive_office_codes?, p_requested_service_year?, p_office_requests?)` → application UUID. Each request is `{scope_id, department_id?: uuid, service_year, office_code}`. Maximum 36; duplicate selections fail atomically. Keep a UUID and exact payload for network retries. Reuse with changed payload fails. This wrapper creates the membership application and requests in one transaction. Never call the legacy submit first.
- `list_membership_office_requests(p_application_id?, p_limit=100, p_offset=0)` → minimal request array. Only applicant or exact-scope authorized reviewer sees a request; ordinary church membership approvers do not automatically see parent/department requests. Contains `can_review`, not a promise that target eligibility/reauth will succeed.
- `review_membership_office_request(p_request_id, p_decision='approve'|'reject', p_reason?)` → `{id,status,changed,assignment?}`. Rejection requires a reason. Authorization is checked before revealing request existence, with current consent and existing server-verified recent Google/AAL2 proof. Approval requires approved active membership in the original church and current target consent, then invokes existing audited assignment RPC. Duplicate same decision is a no-op; an opposite decision is refused. Rejected/withdrawn membership closes still-pending requests.

Existing assignment eligibility is deliberately unchanged: church non-pastor governance offices require executive membership; parent offices require minister/executive membership; pastor requires minister membership. Department office requires an active exact-church member but grants no app role. A request can therefore remain pending until independently approved base eligibility exists. Never auto-upgrade membership because a user selects a parent or department title.

Security: tables have RLS and no client grants, RPCs have pinned `pg_catalog` search path, anonymous execution is revoked, idempotency is actor-bound in private schema, server Seoul service year is authoritative. Approval and assignment/audit commit together. Local pgTAP fixtures roll back and do not alter production accounts.
