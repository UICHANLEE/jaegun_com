# 임원 전용 회의록·회계와 전체 다운로드

2026-10-19, `codex/office-records-and-operations` 후속 변경.

## 동작

- 서버가 확인한 활성 임원 범위가 없으면 웹·SwiftUI 기록 메뉴를 숨긴다. 직접 URL 또는 RPC를 알아도 일반 성도·사역자·임원 역할 없는 관리자는 기록을 열람하거나 내려받을 수 없다. 기존 legacy 테이블의 직접 SELECT도 차단되어 있다.
- 모임 상세의 기록 링크는 정확한 조직/모임으로 연결한다. 기록 화면에서도 조직 공통 또는 특정 모임을 선택하고 날짜별로 수동 작성할 수 있다. 반복 일정은 같은 모임 안에서 기록 날짜로 구분하며 기존 쓰기 직책·서울 연도·revision/operation ID·최근 Google 인증 경계를 유지한다.
- 전체 회의록 / 전체 회계 장부 버튼은 현재 화면의 연도·모임 필터와 무관하게 **본인에게 허용된 모든 정확한 조직 범위·모임·연도**를 하나의 XLSX로 내보낸다. 다른 교회 자료는 포함하지 않는다.
- 한 SQL 문장의 동일 스냅샷으로 기록·이력·개수를 계산한다. 보존된 삭제 표시와 역분개도 포함하고, 영수증 사진 원본은 포함하지 않는다. 기간 결산·기간 마감 기능은 기존대로 별도로 유지한다.
- 긴 본문은 Excel 셀 32,767 UTF-16 제한보다 작은 30,000 단위의 번호 있는 조각으로 나눈다. 본문 / 변경본문 시트에서 기록 ID·버전·분할번호 순으로 연결할 수 있다. 수식처럼 보이는 입력은 실행되지 않는 문자열로 내보낸다.
- 전체 내보내기는 현재 동의·살아 있는 세션·본인 계정·최근 5분 Google 인증·시간당 6회 제한을 확인하고 감사 기록을 남긴다. 계정·동의가 바뀌면 이전 결과로 파일을 만들지 않는다. SwiftUI의 XLSX 생성은 백그라운드에서 수행하고 공유 파일에는 완전 파일 보호를 적용한다.
- 일반 성도에게 과거 `fees` 스태프 위임이 있어도 회계 조회·처리는 허용하지 않는다. 신규 회비 위임도 해당 범위의 활성 임원에게만 가능하다. 비회계 출석·현장 운영 위임은 유지한다. 위임 레코드·장부 데이터를 삭제하지 않았다.

## 검증

- 적용 전 전체 회계/기록 테스트: 최종 89개 통과, 합성 데이터 롤백.
- 적용 후 같은 89개 통과. 실제 사용자 기록의 작성·삭제·제재·위임 변경을 시험 목적으로 실행하지 않았다.
- 적용 후 기존 행사 현장·출석 테스트: 39개 통과, 롤백.
- 최종 웹 전체: 66개 파일 / 510개 테스트 통과, production build 및 배포 번들의 데모 노출 차단 검사 통과.
- 웹 테스트는 일반 회원 메뉴 미노출, 서버 승인 후 메뉴 노출, 모임 범위 링크, 계정 전환, 직접 URL의 접근 불가, 전체 다운로드 버튼 계약, 긴 Unicode 본문의 실제 XLSX 생성/재파싱, 누락 응답 거부를 포함한다.
- SwiftUI 앱 + XCTest 타깃 `build-for-testing` 성공. XCTest를 시뮬레이터나 실기기에서 실행한 결과가 아니다. 기존 Pods 배포 타깃 경고는 남는다.
- 테마 5개 검사, 보호 런타임 28개 파일, 마이그레이션 안전 검사·비밀정보 스캔 통과.

## 제한 / 미확인

- 안전한 동기식 전체 다운로드 한도는 기록 10,000개·이력 40,000개·응답 20MB이며, 초과 시 **부분 파일 없이 명시적으로 실패**한다. 그 이상을 위한 비동기 대용량 내보내기는 별도 구현이 필요하다.
- 실제 사용자 계정으로 브라우저/연결된 iPhone에서 전체 파일을 내려받는 E2E는 이번 턴에 실행하지 않았다. 파일 형식은 합성 자료 roundtrip과 서버 권한 테스트로 확인했다.
- 운영 웹 재배포, iPhone 재설치, App Store 제출은 이번 변경과 별개다. main은 변경하지 않는다.
- 전체 native 출시 RPC gate는 별도 미완성 화상회의·라이브 함수 4개 때문에 여전히 차단된다. `executive-record-rpcs-2026-10-19.json`은 93개 literal 호출 중 89개 존재를 확인한 시점 자료이며 15분 이후 출시 검사용으로 재사용할 수 없다.
- Supabase의 기존 유출 비밀번호 보호 비활성 경고 등 전체 시스템의 미해결 경고를 이번 기능 테스트 통과와 혼동하지 않는다.
